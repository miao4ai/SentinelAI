## 一、量化（Quantization）

### Q1. LLM 的量化是如何实现的？

**核心数学**：把一组 bf16 权重 w 存成低比特整数 q + 一个高精度缩放因子 s：

```
q = round(w / s)      （对称量化；非对称再加零点 z）
w ≈ s · q             （用时反量化）
```

关键设计维度是**共享粒度**：整张量一个 s（误差大）→ 每通道一个 → **每 64/128 权重一组一个**（主流做法）。粒度越细误差越小，但缩放因子的存储开销越大（NF4 约 0.13 bit/权重，bnb 的 `double_quant` 还把缩放因子再量化一次）。

**两条路线**：

1. **Weight-only（W4A16，LLM 推理主流）**：只压权重，激活保持 bf16。kernel 边读边反量化，乘加仍走 fp16 tensor core。为什么反而快：decode 阶段每个 token 都要把全部权重从显存搬一遍，**瓶颈是访存带宽不是算力**，权重体积压到 1/4 ≈ 搬运时间省 3/4。
2. **Weight+Activation（W8A8）**：权重和激活都变 int8，直接用 INT8 tensor core。难点是 transformer 激活里的**离群通道**（幅值大几十倍）——LLM.int8() 把离群维度拆出来走 fp16；SmoothQuant 数学等价地把激活的"难度"迁移到权重上。

**代表算法**：

| 方法 | 实现思路 | 要校准数据吗 |
|---|---|---|
| bnb NF4（我们 QLoRA 用的） | 就近取整，但 16 个格点按**标准正态分位数**摆放（训好的权重近似正态，格点信息利用率最优）；每 64 权重一组 absmax 缩放 | 不要，加载时现算 |
| GPTQ | 逐层最小化 ‖WX−ŴX‖²：一列列量化，用二阶信息（Hessian≈XXᵀ）把误差补偿到未量化的列 | 要 |
| AWQ | ~1% 显著权重通道（按激活幅值找）决定大部分精度；量化前给它们乘保护性缩放（逆缩放吸收进上一层，数学等价），再普通取整 | 要（只统计幅值） |

**和训练的关系**：上面全是 PTQ（训练后量化）。QAT（量化感知训练）用直通估计器训练时模拟量化，LLM 上少用。**QLoRA 是聪明的折中**：底座 PTQ 冻结，旁挂可训练 bf16 LoRA——量化误差有机会被 LoRA 顺带补偿，这是 4-bit 底座还能微调到 AUC 0.990 的原因之一。

### Q2. 高精度缩放因子 s 是怎么得到的？是超参还是学出来的？

**都不是——绝大多数方案里 s 是从权重本身"算"出来的统计量**，按成本分三档：

1. **闭式统计（bnb/NF4 这档）**：`s = absmax(block)`，加载几秒内完成，无数据无训练。真正的超参只有块大小 64 和格点表；s 是导出量。absmax 意味着格点范围必须罩住块内最大权重——**块里有一个离群值，其余 63 个的精度就被牺牲**，这正是"每 64 一组"而非每层一组的原因。
2. **校准数据上搜出来的（GPTQ/AWQ）**：`s = α·absmax`，在小网格上搜使 ‖WX−ŴX‖² 最小的裁剪系数 α——故意裁掉极端离群值，换主体权重的分辨率。是优化但没有梯度。
3. **真·learned（QAT 世界）**：LSQ 把 s 设成 `nn.Parameter` 随任务 loss 梯度下降；OmniQuant 只对裁剪参数做轻量反传。精度上限更高但要训练管线，LLM 推理生态少用。

QLoRA 里 s 始终冻结；量化误差由旁路 LoRA 在训练中补偿——效果上像"把第三档的学习转嫁给了 LoRA"。

### Q3. 嵌入 + lm_head 那 ~2.2GB（bf16）能压缩吗？

能，四档（背景：bnb 默认跳过它们——嵌入是查表不是 GEMM；lm_head 是最后一层投影，量化误差不经任何后续层稀释，直接重排 logits，是全模型最敏感的一层）：

| 方案 | 省多少 | 代价 |
|---|---|---|
| int8 行量化嵌入+lm_head | 2.2→1.1GB | 查表本是访存瓶颈，几乎无感；lm_head 的 logits 轻微扰动 |
| AWQ/GPTQ 整模型 | 总显存 ~5GB | 它们通常也把这两块留 fp16，压的还是线性层 |
| 权重绑定（tied embedding） | 直接砍半、零损失 | 必须训练时绑定；Qwen2.5 只在 0.5B/1.5B/3B 绑了，7B 没绑，事后绑不了 |
| 任务专用分类头：打分只读 yes/no 两个 logit，152k×3584 → 2×3584 | lm_head 1.1GB→**14KB** | 只能打分不能生成解释；与 §4.10 两模式部署天然契合 |

L4 24GB 上这块不是瓶颈，维持默认即可；这套手段是为下沉到 8GB 边缘设备准备的。

### Q4. 什么是权重绑定（weight tying）？

嵌入表 E（V×d）和 lm_head W（d×V）形状互为转置、语义互为反向（查表：token→向量；投影：向量→每个 token 的 logit = h·w_t）。绑定即令 **W = Eᵀ**，只存一份：预测下一个词变成"拿隐状态和每个词的嵌入做点积找最像的"，语义自洽（Press & Wolf 2016，GPT-2 在用）。

小模型绑定后困惑度往往更好（互相正则化）；大模型不绑，因为：①输入侧要"这个词长什么样"、输出侧要"分类边界方向"，参数够多时让两者分化能榨出精度；②模型越大嵌入占比越小，省显存动力小。**事后绑不了**：训练时独立更新的 E 和 W 早已漂移成两个矩阵，强行 W=Eᵀ 等于换上没训过的输出层，恢复精度需要不小的继续训练。

## 二、视觉编码与多帧输入

### Q5. 一张照片输入后，image encoder 是 ViT 吗？

是，但为 VLM 改造过。一张照片的完整旅程：

```
照片 (任意分辨率)
 ① smart_resize 到 28 的整数倍, 归一化
 ② 14×14 patchify（实现是 Conv3D, kernel=(2,14,14); 单图时间维复制成 2 份）
 ③ 32 层 transformer (hidden 1280, 16 头)：2D RoPE 位置编码,
    大部分层 112×112 窗口注意力, 仅 4 层全局
 ④ PatchMerger: 相邻 2×2 patch 拼接 → 两层 MLP → 3584 维 LLM token
 ⑤ 插进 <|vision_start|>…<|vision_end|>, 交给 28 层 LLM
```

和经典 ViT 的五处不同：**无 CLS token 无分类头**（全部 patch token 交给 LLM，聚合留给注意力）；**原生动态分辨率**（2D RoPE 解析计算行列坐标，不像学习式绝对位置嵌入绑死训练分辨率）；**窗口注意力**（大图编码成本从平方降到近线性）；**RMSNorm+SwiGLU**（与 LLM 组件对齐）；**时间维预留**（Conv3D 的 temporal_patch_size=2 为视频准备，单图复制自己适配）。

项目里三种视觉编码器构成演化线：I3D（3D CNN，卷积+池化硬聚合）→ CLIP ViT（CLS 聚合成单向量）→ Qwen2.5-VL ViT（不聚合，全 token 保留）——信息保留量逐级上升，与任务表现排序一致。

### Q6. 多帧输入的 pooling 是如何实现的？

严格说**几乎没有传统 pooling**——只在空间维做一次"学习型压缩"，时间维完全不池化：

1. **空间**：PatchMerger 把相邻 2×2=4 个 patch 的向量**拼接**（非平均）后 MLP 投影成 1 个 token。224×224 帧 → 256 patch → **64 token/帧**。
2. **时间**：8 张独立 image 各自过 ViT、各出 64 token、按序排队共 512 个，帧间零合并。跨帧关系靠 **M-RoPE**（见 Q10）+ LLM 自注意力建立——"时序聚合"从固定池化算子升级为按内容自适应的注意力聚合。
3. **video 输入的差别**：传 `{"type":"video"}` 时 Conv3D 把相邻两帧打包成一份 token（2× 时间压缩），M-RoPE 的 t 坐标按真实时间戳走。

这解释了 VLM 与融合模型的本质差别：I3D 特征**先 mean-pooling 再分类**——6 分钟片段里 10 秒的暴力被平均稀释（错误分析里那批 FN 的成因）；VLM **先保留全部 token、推理时注意力自己找**——聚合发生在推理之后而不是之前。

### Q7. 这种注意力聚合和我们实现过的 attention pooling 是一回事吗？

同一家族（聚合权重由内容算出，query·key→softmax→加权和），但差几个台阶。演化链在仓库里每级都有实物：

| 层级 | 聚合权重怎么来 | 跳数 | 仓库对应 |
|---|---|---|---|
| mean pooling | 固定均匀权重 | 1 | I3D 特征平均（稀释型 FN 元凶） |
| attention pooling | 训练后冻结的 query 常量 | 1 | 融合模型池化头 |
| cross-attention | query 来自另一模态的内容 | 1-2 层 | ⑥（音频+文本当 Q，帧当 K/V） |
| LLM 自注意力 | query 来自**不断演化的推理状态**，被提示词条件化 | 28 层×多头 | Qwen2.5-VL |

三个关键差异：**query 的活性**（常量 → 逐样本 → 逐层动态且被"有没有暴力"这个问题实时引导）；**跳数**（池化一锤定音 vs 几十层迭代、token 互相注意）；**聚合与推理的次序**（先聚合后分类 vs 聚合就是推理的副产品——生成 yes/no 的 token 对 512 个视觉 token 做的最后一次注意力，等价于"以完整推理状态为 query 的 attention pooling"；前 27 层是在为这次 pooling 准备越来越好的 query）。

实验数字吻合梯度：4490 规模 ⑤ 0.930 → ⑥ 0.937（一跳自适应的小步收益），稀释型 FN 要到 VLM 才解决。

### Q8. 为何 LLM 是 28 层？

28 = Qwen2.5-7B 的 `num_hidden_layers`，是"总参数 ~7B + 宽度 3584"预算下凑出来的商：每层 attention(GQA) ~29M + MLP ~204M ≈ 233M，×28 ≈ 6.5B，加嵌入/lm_head 1.1B ≈ 7.6B。

深宽权衡：①scaling law 显示固定参数下宽深比在 ~100-200 有很宽的平台（Qwen 3584/28=128 落在中心；Llama-3-8B 32×4096 也是 128）；②深度=串行组合步数，多跳推理需要电路深度；③深度的代价是 decode 延迟（层必须串行过）；④head_dim 固定 128 是 kernel 甜点尺寸，3584=28×128（头数 28 与层数 28 只是巧合）。真正重要的不是 28 这个值而是量级：聚合-推理被迭代几十次，而 attention pooling 只有 1-2 次。

## 三、M-RoPE 专题（Multimodal Rotary Position Embedding）

### 先复习一维 RoPE

RoPE 不往 token 向量里**加**位置信息，而是在算注意力前把 Q、K 向量按位置**旋转**：把 head_dim 维向量看成 d/2 个二维平面，第 i 个平面旋转角度 = 位置 m × 频率 θᵢ（θᵢ 按维度指数递减，像不同快慢的钟表指针）。妙处在于旋转的性质：

```
⟨R(m)q, R(n)k⟩ = ⟨q, R(n−m)k⟩      —— 注意力分数只依赖相对位置 n−m
```

绝对位置在点积中自动消掉，模型天然获得相对位置感、且比学习式位置嵌入更容易外推到没见过的长度。

### M-RoPE：把一个位置拆成三个坐标

文本是一维序列，一个位置号够用；但视觉 token 天生带三维身份——**第几帧（t）、帧内第几行（h）、第几列（w）**。M-RoPE 的做法：

1. **把 head_dim 的旋转平面切成三组**，分别负责 t、h、w（Qwen 的切分约为 16/24/24 个平面）；
2. 每个 token 的位置不再是一个数，而是三元组 **(t, h, w)**，三组平面各按自己的坐标旋转；
3. **文本 token 退化兼容**：三个坐标取同一个递增序号 t=h=w=m，此时 M-RoPE 严格等价于普通一维 RoPE——文本能力零损失。

以我们的 8 帧输入为例（每帧 8×8=64 个 merge 后 token）：

```
第 1 帧的 token:  (t=0, h=0..7, w=0..7)
第 2 帧的 token:  (t=1, h=0..7, w=0..7)
   ⋮
提示词文本 token: (t,h,w) = (8,8,8), (9,9,9), …   ← 三坐标同值, 退化为 1D RoPE
```

### 它买到了什么

1. **空间关系是解析的**：同帧内两个 token 的注意力自动携带"相隔几行几列"的相对几何——"左边的人打了右边的人"有了坐标依据；
2. **跨帧对应**：不同帧同一空间位置的 token 只差 t 坐标——"同一位置随时间怎么变"（动作！）变成注意力容易读出的模式，这正是暴力检测最需要的信号；
3. **分辨率/时长外推**：旋转是解析函数，没见过的行列数、帧数照转不误——动态分辨率（Q5）和长视频都靠它；
4. **绝对时间对齐（Qwen2.5-VL 的增量）**：video 输入时 t 坐标按**真实时间戳**走而非帧序号——采样率变化不会扭曲时间感，模型能回答"第几秒发生了什么"；我们用 8 张独立图的方式则放弃了时间戳信息，自己控制采样。

一句话：**M-RoPE 让"位置"从一个标量升级为(时间,行,列)三维坐标，且对纯文本自动退化**——它是多帧 token 排成一队后，LLM 仍知道"谁在哪一帧的哪个位置"的全部依据，也是 Q6/Q7 里"注意力自适应聚合"能够按空间和时间寻址的基础设施。

## 四、SFT 与 QLoRA

### Q9. SFT 和 few-shot learning 的区别？

一句话：**SFT 把知识写进权重，few-shot 把知识塞进上下文**。

| | SFT | Few-shot（in-context learning） |
|---|---|---|
| 机制 | 梯度更新权重 | 示例放 prompt 里，权重不动，注意力现场模仿 |
| 持久性 | 永久 | 一次性，每条请求重新带例子 |
| 数据量 | 千~万级（我们 3.3k） | 1~几十条 |
| 成本 | 训练付一次，推理零开销 | 训练零成本，每次调用付示例 token 费 |
| 深度 | 能改校准、决策边界、格式习惯 | 只能唤起已有能力 |

我们跳过 few-shot 的原因：多模态示例太贵（1 示例=8 帧×64=512 token，4 个示例每次调用多烧 2000+）；且零样本的短板是**校准**（P(yes) 压太低）——校准恰是 few-shot 最难修、SFT 最容易修的。few-shot 的主场是任务多变/无训练管线/标注极少的快速原型，与 SFT 是接力关系：**few-shot 打样，SFT 定型**。

### Q10. 这个 SFT 里什么是"打开"的？

只有 **LoRA 旁路的 A/B 矩阵，~40M 参数（0.57%）**。开关清单：

| 组件 | 参数量 | 状态 |
|---|---|---|
| LoRA A/B（28 层 × 7 投影） | ~40M | ✅ 打开（bf16，有梯度有 AdamW 状态） |
| LLM 的 W₀ 本体 | ~6.5B | ❄️ 冻结（4-bit，梯度只穿过不更新） |
| 视觉塔 + PatchMerger | ~0.67B | ❄️ 冻结 |
| 词嵌入 / lm_head | 各 ~0.54B | ❄️ 冻结 |
| RMSNorm/bias | 极少 | ❄️ 冻结（升 fp32 只为数值稳定） |

实现：`prepare_model_for_kbit_training` 先把全模型 `requires_grad=False` 一刀切，`get_peft_model` 再按名字匹配 `q_proj` 等**只打开新挂的 A/B**。细节：ViT 内部注意力叫 `qkv`（融合命名）不叫 `q_proj`，所以视觉塔是被命名巧合"顺带"冻住的——换模型要自己确认。

### Q11. 是不是"整个模型冻结，外面盖一层可学习的小矩阵"？

前半对，后半的空间想象要修正：**不是盖在外面的一层被子，而是缝进每层内部的 196 块并联补丁**。

```
每层:  h = W₀x ──┬──→ 相加
                 └ B·A·x ┘     ← 补丁并联在这层内部（28 层 × 7 投影 = 196 块）
```

区别决定两件本质的事：①**表达能力**——只在最外层加矩阵等于冻结特征上的线性探头，中间 28 层的计算改不了；并联在每层内部等效于每层权重变成 W₀+(α/r)BA，**前向的每一步都被微调**（只是改动约束在 16 维低秩子空间）；②**可合并性**——补丁与本体是同位置加法，训完可 `merge_and_unload` 把 BA 加进 W₀ 变回普通模型；盖在外面的被子合并不进去。

### Q12. "adapter on/off"里的 adapter 是什么？和 CV 塔-LLM 之间的对齐 adapter 是一回事吗？

**不是一回事——"adapter"一词两义**：

| | 模态对齐连接器 | LoRA adapter（§8.2 说的） |
|---|---|---|
| 位置 | 视觉塔与 LLM **之间**，串联在数据通路上 | LLM 28 层**内部**，并联在投影旁 |
| 作用 | 把视觉特征(1280 维)翻译成 LLM 空间(3584 维)的 token | 把任务口径写进模型行为 |
| 在 Qwen2.5-VL 里 | **PatchMerger** | `qwen_qlora_adapter/` 那 190MB |
| 谁训的 | 阿里预训练时，属于底座本体 | 我们 SFT 时，是外挂 |
| 能拆卸吗 | 不能（拆了视觉 token 进不了 LLM） | 能（`disable_adapter()` 一行切回零样本） |

词源撞车：BLIP-2 的 Q-Former、LLaVA 的 projection 常被叫 adapter（把视觉适配给语言）；PEFT 社区把插件式微调模块也叫 adapter（把底座适配给任务）。数据通路上一串一并：

```
8帧 → ViT(冻结) → PatchMerger(冻结) ←串联的"对齐adapter"
                      ↓ 512 视觉 token
             LLM 28层(W₀ 冻结) ‖ 每层并联 B·A ←我们训的 LoRA adapter
                      ↓
                   yes / no
```

adapter on/off 开关的只是并联补丁；PatchMerger 永远在工作。on/off 的价值：**成对评测零成本**（同模型前向两遍，差异 100% 归因微调）+ **两模式部署**（打分时开、要零样本完整解释能力时关）。

### Q13. 是不是因为模型 reasoning 变强，所以 SFT 的 epoch 数才这么小（1 epoch）？

方向对，机制再校准：**不是 reasoning 强，而是预训练底子厚——SFT 从"教学"变成了"调口径"**。

1. **SFT 学的东西很薄**（LIMA 的 elicitation 论）：零样本 AUC 0.900 说明"什么是暴力"预训练就会；1 epoch 只是把校准拉正。要学的 ΔW 小（LoRA 低秩假设成立的同一原因），几千步就到位——epoch 末 loss 已 0.10，再转一圈主要在背答案。
2. **多 epoch 有害**：记忆样本、输出分布变尖（校准恶化，伤级联路由带）、灾难性遗忘（1 epoch 已见轻微解释能力磨损）。业界 1~3 epoch 是常态。
3. **真正的分界线是"从头学 vs 适配"**，仓库里就有对照：① early 融合 transformer 从随机初始化学起要 **200 epoch**；BERT（不会 reasoning）下游微调也只要 2-4 epoch——变量是预训练底子与任务的距离，不是推理能力。Reasoning 强是"底子厚"的伴生现象。
4. 时代注脚：教真正的新能力（长链推理/工具使用）现在靠 RL/蒸馏而不是堆 SFT epoch；SFT 学不动时的正确反应是换范式，不是加 epoch。

### Q14. §8.3 那张成对指标表怎么解读？

七行数字讲一个故事：**零样本"什么都看得懂，就是不敢说"**。

1. **病症签名**：P=1.000 + R=0.177——184 条暴力只喊了 ~33 次 yes 但全对。不是不认识暴力（AUC 0.900 排序完好），是 P(yes) 整体压太低——**知识在，口径歪**。
2. **QLoRA 收益拆两笔**：校准（F1 +0.647、Recall +0.758 的主体，直方图可见分布被拉开对齐 0.5）；排序（AUC 0.900→0.990 = **错排率 10%→1%，降 10 倍**，这部分阈值救不回来——只做 oracle 阈值校准 F1 约到 0.85，到不了 0.948）。
3. **两行"不变"**：p@top10% 双满分——头部从来不是问题，收益在排序中段和固定阈值处（46% 基线下该指标顶格 lift 2.17，天花板低）；Precision −0.039 是唯一代价行——每 100 条标记多 4 条误报换多抓 4 倍暴力，审核场景划算但不免费（"LoRA 误报税"）。
4. **读表纪律**：n=400，AUC 置信区间 ±0.01，别对第三位小数做文章；全是 XD 同域，跨域时零样本反而更稳（§4.10）；0.5 是任意阈值，F1@0.5 度量的是开箱即用性不是能力上限。
