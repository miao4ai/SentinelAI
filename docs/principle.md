# 一、CLIP 零样本审核机制（第五章）

承接 Lecture 7（CLIP / 对比学习**原理**）：上一讲讲 CLIP 怎么**训练**出图文共享空间；
这一节讲怎么**用**它——不训练、只写几句 prompt，就做违规**初筛**。对应代码
`sentinelai/clip_screener.py`，真实结果见 `experiments.md §9`。

## 1. 为什么能"零样本"：共享空间的一次免费午餐

V1 视觉专家的困境：ImageNet 的 1000 类里**没有"暴力"这个类**，想判暴力就得自己
标注数据、训练一个分类头。

CLIP 把这一步整个绕过。它训练完就有一个性质（Lecture 7）：**图像**和**描述它的
句子**被放到**同一个向量空间**里、语义相近就距离相近。于是：

> "这帧像不像暴力" ≈ "这帧的 embedding 离句子 *'people fighting'* 的 embedding 近不近"

判定被转成一次**相似度查询**，不需要任何训练。这就是 zero-shot：目标类别在训练里
从没出现过，靠**自然语言描述**即时定义。**写 prompt = 定义类别。**

## 2. Prompt 池设计（5.2）

```
违规 prompt（每类多写几句同义改写）        安全对照 prompt（关键！）
  violence: "people physically fighting"     "people hugging"
            "violently attacking another"     "people talking calmly"
            "threatening with a weapon"       "food being prepared in a kitchen"
  nsfw:     "explicit sexual content" ...     "a normal everyday photo" ...
```

两个设计点：

- **每类多写几句**：同义改写让信号更稳，不押宝在单一句子的措辞上。
- **必须有"安全对照"prompt** —— 这是最容易漏、也最关键的一步。softmax 是**相对**的：
  如果池子里**只有违规 prompt**，那正常帧也只能把概率质量分给违规 prompt（矬子里
  拔将军），于是**一切都"违规"**。安全 prompt 的作用是**吸走正常帧的质量**，把它们的
  违规分数压下去。
  - 典型例子：厨房切菜 vs 持刀威胁。加一句 *"food being prepared in a kitchen"*，
    就把"切菜"的质量从"weapon"prompt 那里拉回来，减少误报。

## 3. 打分：余弦相似度 → softmax → 按类聚合（5.3）

```
帧 ─▶ image encoder ─▶ 投影 ─▶ L2 归一化 ─┐
                                          ├─▶ 余弦相似度(点积) ─▶ ×温度 ─▶ softmax
prompt 池 ─▶ text encoder ─▶ 投影 ─▶ 归一化 ┘        (在所有 prompt 上得到一个分布)
```

- **余弦相似度**：两边都 L2 归一化后做点积，就是夹角余弦（只看方向、不看长度）。
- **×温度再 softmax**：乘上 CLIP 训练时学到的 `logit_scale`，再 softmax 成 prompt 上
  的概率分布。温度控制分布的"尖锐度"。
- **按类聚合**：某一类的分数 = 该类**所有违规 prompt 的质量之和**（用 sum 不是 max：
  同义改写是"或"的关系，帧在两句 violence 上各 0.3 就是 0.6 暴力）。
- **违规总分** = 所有违规 prompt 质量之和 = `1 − 安全 prompt 质量之和`。

**工程要点**：

- prompt 池是**固定的**，所以只编码一次；之后每帧只要一次 image-encode + 一个矩阵乘，
  很便宜。
- 实现上走 CLIP 的完整 forward 取 `logits_per_image`（内部帮你做好投影+归一化+温度，
  且**跨 transformers 版本稳定**），不要用 `get_text_features`——它在 5.x 改了返回类型。

## 4. 帧 → 片段：为什么用 max 池化

一个片段抽 K 帧，每帧一个违规分，**片段分 = 帧分的最大值**。

- 初筛逻辑是"**任一帧像暴力，就该标记送审**"，所以取 max。
- 若用 mean，一个几帧的短暴力镜头会被大量正常帧**稀释**掉，漏筛。

## 5. 怎么读结果 + 校准陷阱（连到 exp5）

真实 XD（299 片段、零训练）：**AUC 0.825**、**precision@top-10% 0.931**。但——

- 正常片段的违规分**中位也有 0.87**（暴力 0.97）。**绝对分数没校准**：CLIP 总倾向给
  违规 prompt 也分一杯羹，安全 prompt 没能吸走全部质量。
- 所以**别用 0.5 当阈值**（会几乎全标记：recall 1.0、precision 0.52）。它是一个
  **排序信号**——按分数排序、取 top-k 或用高阈值(如 0.91)送审。
- **定位：初筛，不是终判**。0.825 明显低于训练好的融合（① early **0.951**）。
  CLIP 零样本 = **便宜的第一道粗筛**，把最可疑的一批快速挑出来（top-10% 里 93% 真
  暴力），只把高分片段送给贵的下游专家/融合做**终判**。两者是**流水线上下游**，不是
  替代。

## 6. 中文 / 其他语言

prompt 的**语言和视频无关**（视频只是像素）。处理中文内容时，把模型换成
Chinese-CLIP（`OFA-Sys/chinese-clip-vit-base-patch16`）+ 中文 prompt 即可；
`clip_screener.py` 的 `--model` / `model_name` 已留好接口。

## 一句话总结

CLIP 把"这帧违规吗"变成"这帧离哪句描述更近"，于是**写 prompt 就等于定义类别**，
不训练就能做又快又便宜的违规**初筛**；代价是**分数只可比、不可信**（要用排序或高阈值），
终判仍交给训练过的融合。

# 二、融合位置的原理：为什么 ①②③⑤ 各有胜负

`fusion_layers.md` 讲了五层**怎么实现**；这一节讲**原理**——每个位置背后是什么机制，
以及它在我们真实实验里为什么这样表现（数据见 `experiments.md` §7、§7.1、§8）。
这里聚焦 **①②③⑤**（④ 在下一节单独说）。

## 0. 一根主轴：越早融合 = 交互越多，但越吃数据

把四个位置排在一条流水线上，区别只有一个：**三个模态在管线的哪一步"相遇"。**

```
原始 token ────► 池化特征 ────► 各自 embedding ────► 各自最终概率
    │                │                 │                    │
    ① early        ③ feature        ② coordinated        ⑤ late
  (最早相遇)                                            (最晚相遇)

  ◄─────────── 能建模的跨模态交互越多 ───────────
  ─────────── 越鲁棒、越省数据、越难过拟合 ──────────►
```

相遇得越早：模型能学的**跨模态交互**越多（谁该关注谁、哪几帧配哪段音），
天花板越高——但参数多、要从零学交互，**越吃数据、越容易过拟合**。
相遇得越晚：能玩的花样越少，但**几乎无参数、不会过拟合**，是出了名的强 baseline。

**"最佳位置"不是固定的**，取决于三件事：数据量、模态强弱是否均衡、信号是否真需要
跨模态交互。我们的实验正好把这条轴上的**交叉点**跑了出来。

## ① Early（原始 token 上的联合 transformer）

**原理**：不先池化，直接把每个模态的 token 序列（视频帧、音频窗、文本词）投影到同一
维度，拼成一个大序列，丢进一个共享 Transformer，让**注意力自己去找**哪几个 token
携带信号、并让模态之间**从一开始就互相 attend**（"听到尖叫→重点看这几帧"）。

- **最强表达力**：唯一能建模 token 级跨模态交互的位置。
- **代价：最吃数据**。参数最多、交互要从零学起，数据少时学不动、还过拟合。

**证据（交叉点）**：788 片段时 ① 只有 0.926，输给 ⑤（0.949）——数据饿着。
配对数据放大到 4502 后，① **反超到 0.945**，std 从 0.022 砍到 0.009；再喂真实音频
token 到 **0.951**，稳居第一。**原理印证：早融合天花板最高，但要数据喂饱才兑现。**

## ② Coordinated / CLIP 式（各自编码 → 对齐到共享空间）

**原理**：每个模态**保留自己的编码器**，但通过训练把它们**拉进同一个向量空间**，于是
可以用几何（余弦相似度）来比较和组合。不像 ① 那样把 token 搅在一起，而是"各自成型、
再对齐"——一种**结构化的中间地带**（对比学习详见本文第一节 / Lecture 7）。

- **对模态质量不均衡最鲁棒**：对齐是学出来的，模型能学会**把弱模态摆在合适的位置/权重**，
  不被它拖下水。
- 比 ③ 结构化，比 ① 省数据。
- **归类**：这是**经典的 fusion 方法**——**embedding / model-level fusion（表示级、中间层融合）**，
  CLIP 是它的代表作。它训练时用对比**对齐**，但作为组合多模态做预测的方法就是 fusion；
  和 ⑥ cross-attention 的"fusion vs alignment"之辨见**第四节第 7 小节**。

**证据**：3 模态里加入弱文本（单模态才 0.739）时，naive 晚融合 ⑤ 从 0.949 **降到
0.941**（被稀释），而 ② coordinated 反而**升到 0.939**——它学会了不被弱模态拖累。
**原理印证：协调表示 = 学习式、结构化、对模态强弱差异鲁棒。**

## ③ Feature-concat（各自池化 → 拼接 → 浅层分类器）

**原理**：在**特征层**融合，但已经**池化掉了时序结构**——把每个模态的池化向量首尾拼成
一个大向量，过一个线性/浅 MLP。分类器能给不同维度（不同模态）**学权重**，但**没有
token 级交互**。

- **便宜的中间选项**：比 ① 省参数省数据，又比 ⑤ 多了"联合加权"的能力。
- 丢掉的是时序/token 交互——它看不到"哪一帧配哪段音"。

**证据**：一直在中游，数据变多时小幅上升（0.928→0.937）。**原理印证：稳妥的中庸——
拿到了联合加权，牺牲了交互深度。**

## ⑤ Late / Vote（各模态各出概率 → 加权平均/投票）

**原理**：**完全不做联合学习**，只在**最终决策**上合并——每个模态独立出一个概率，然后
加权平均（或投票）。

- **几乎无参数 → 不会过拟合**，是极强的 baseline。当各模态**本身强、且相对独立**时，
  它们的错误**去相关**，一平均就是近最优集成。
- **两个致命盲点**：(1) 学不会给弱模态降权（权重是写死的）；(2) 完全看不到跨模态交互。

**证据**：小数据（788）时**稳稳最好**（0.949）——集成的鲁棒性在数据稀缺时最值钱。
但加入弱文本后被稀释（→0.941），且一旦 ① 数据喂饱就被反超。**原理印证：晚融合 =
鲁棒集成，数据少 / 模态强而独立时最优；但对交互和模态质量差异都"瞎"。**

## 把四个位置的原理并排

| 位置 | 在哪相遇 | 能建模交互 | 吃数据 | 对弱模态 | 什么时候赢 |
|---|---|---|---|---|---|
| ① early | 原始 token | 最强（token 级） | 最多 | 靠数据 | 数据充足、需跨模态交互 |
| ② coordinated | 各自 embedding | 中（几何对齐） | 中 | **最鲁棒** | 模态强弱不均、要学权重 |
| ③ feature | 池化特征 | 弱（维度加权） | 少 | 一般 | 便宜中庸、数据一般 |
| ⑤ late | 最终概率 | 无 | 几乎 0 | **最差** | 数据少 / 模态强且独立 |

**一句话原理**：**越早融合，能学的跨模态交互越多、天花板越高，但越吃数据、越易过拟合；
越晚融合，越鲁棒省数据，但对交互和模态质量差异越瞎。** 所以随着数据从 788 涨到 4502，
最优位置就从 ⑤（晚）滑到了 ①（早）——这不是谁绝对更好，是**数据量在这条轴上移动了最优点**。

# 三、决策级融合 ④ 的原理：⑤ 的"学习版"

承接上一节（①②③⑤ 原理）。④ 和 ⑤ **输入相同、机制不同**，单独讲清楚。实验证据见
`experiments.md` §7.1（2 模态）与 §8（3 模态）。

## 1. ④ 是什么：在"最终概率"上再学一层

各模态先各自出一个概率——**和 ⑤ 完全一样的输入**。区别在合并方式：

```
                 视觉 p_v ┐
                 音频 p_a ├─► ⑤ late:  固定加权平均   (无参数)
                 文本 p_t ┘   ④ decision: 喂给一棵可学习的树/GBDT (有参数)
```

- **⑤** 把这几个概率**写死地平均**。
- **④** 把它们喂给一个**可学习的组合器**（决策树 / GBDT / 元分类器），让它**学"怎么合"**。
  树能学**非线性 / 条件规则**：*"音频=枪声 或 视觉=打斗 → 暴力"*、*"文本不可信时忽略它"*。

所以 **④ = ⑤ 的学习版**。

## 2. 关键工程：stacking 必须用 out-of-fold 概率训练（防泄漏）

把"各模态概率"当特征、再训一个元学习器，这叫 **stacking（堆叠泛化）**。有个必须避开的坑：

- ❌ 不能用**测试折**的概率训练元学习器——直接泄漏。
- ❌ 也不能用"各模态在**自己训练数据**上的预测"来训——那些预测**过于乐观**（模型见过这些样本），
  元学习器会学到虚假的高置信，一到真实数据就崩。
- ✅ 正确做法：**训练集内部再做一层交叉验证**（我们用**电影分组 3 折**），生成 **out-of-fold
  概率**来训练树；然后各模态在全训练集上重训、对测试折出概率，交给树组合。

代码即 `exp2_full_audio.py` / `exp3_three_modal.py` 里的 `oof_probs()`。

## 3. 核心原理：为什么 2 模态时它没用、3 模态才"活过来"

④ 能学的东西是——**"在什么情况下更信哪个模态"**。这需要输入之间**有质量差异、有可利用的
条件结构**。于是：

- **2 模态（视觉+音频，都强且相近）**：只有 2 列概率、质量相仿，树**几乎没有规则可学**，
  只是给固定平均**平白加了过拟合方差** → 我们实测它是**所有融合里最差的**（0.931，§7.1）。
- **3 模态（+弱文本 0.740）**：多了一个**明显弱**的模态，树可以学*"给文本降权"、"文本和音频
  冲突时信音频"* → **追平 ② coordinated（0.939），且 std 更小（0.012 vs 0.024）**（§8）。

> **一句话规律：④ 的价值 ∝ 模态数 × 模态质量差异。**
> 模态越多、强弱越不齐，可学习的决策级融合越有料；模态少而齐时它不如直接平均。

这也正好回答了"为什么 3 模态那张表一开始缺 ④"——不是原理上不该有，而是 3 模态恰恰是它
该发力的地方，值得补上（现已补，见 §8 第 5 点）。

## 4. ④ vs ⑤ vs ②：三者的关系

| | 在哪一层合并 | 会学吗 | 能降权弱模态吗 | 风险 |
|---|---|---|---|---|
| ⑤ late | 最终概率 | ❌ 固定平均 | ❌ 学不会 | 无（最鲁棒）|
| **④ decision** | 最终概率 | ✅ 树 | ✅ 能 | 过拟合（靠 OOF+浅树压）|
| ② coordinated | 各自 embedding | ✅ 对齐 | ✅ 能 | 要训、要数据 |

- ④ 和 ② **在 3 模态里打平（都 0.939）**，很有意思：**两条不同的路**——④ 在**概率层**用一棵树、
  ② 在**embedding 层**用几何对齐——**殊途同归**地实现了"对弱模态鲁棒"。
- ④ 比 ② 便宜（不用训深模型），还能给**特征重要性**（哪个模态更被信），可解释性好。

## 5. 什么时候该用 ④

- 模态**多（≥3）、强弱不齐**，且想要一个**便宜、可解释**的组合器（树能输出特征重要性）。
- 各模态概率**本身已经比较可靠**——④ 只在决策层动手，**救不了烂的单模态**。
- 想比 ⑤ 更聪明、又不想像 ①/② 那样重训深模型时的**折中选项**。

## 一句话总结

④ 是 ⑤ 的可学习版：把固定平均换成一棵树。它的用处**随模态数和质量差异增长**——2 模态无料
可学（最差），3 模态加了弱文本就活过来（追平 ② 且更稳）。工程上要用 **out-of-fold 概率**
训练防泄漏。

# 四、Cross-Attention 时空深度融合（第六章）

前面 ①②③⑤ 都是把模态**对称**地合并。第六章（V2）换一种思路：**非对称**的深度融合——
让一个模态**主动 attend 进**另一个模态的逐帧特征里。对应代码 `sentinelai/cross_attention.py`
（层）+ `sentinelai/train/lit_module.py`（Lightning 训练），真实结果见 `experiments.md §10`。

## 1. 6.1 为什么需要时序特征：单帧分不清"切菜"和"捅人"

一张静止的帧里，"厨房切菜"和"持刀捅人"可能长得差不多——**区别在帧间的运动**（挥刀的
轨迹、身体的动作）。所以要用**时序特征**：把连续多帧一起编码，让模型看到 **motion**。

- 我们用 **I3D**（Inflated 3D CNN）的 `(T, 2048)` 序列——3D 卷积本身就跨帧，已含短时运动。
- ROADMAP 6.1 点名的 **VideoMAE / TimeSformer** 是 transformer 版的时序编码器（要从原始帧重抽）。
  **我们抽了两版 VideoMAE（自监督 + Kinetics 监督）换上去——都打不过 I3D，监督版还更差**
  （见下第 6 节的负结果）。**"架构更高级 / 更监督"不等于"特征更好用"——特征要对 task。**

## 2. 6.2 Cross-Attention：Query 是"找什么"，Key/Value 是"在哪"

注意力的三件套在这里有明确分工：

```
Query  (Q) = 音频/文本特征     ——「我在找什么」（听到尖叫？读到威胁？）
Key    (K) = 视频每帧特征       ——「候选位置的索引」
Value  (V) = 视频每帧特征       ——「取回的内容」

     attn = softmax(Q·Kᵀ / √d) · V
```

- 一段**尖叫的音频 Q** 去和每一帧的 K 点积——和"暴力帧"的 K 更像 → softmax 后**权重集中在
  那几帧**，V 就把这些帧的内容取回来。直觉：**"听到尖叫时，重点看这几帧。"**
- 这就把"音频线索"和"视频里对应的时刻"**对齐**了——正是单模态或对称融合做不到的**定位**。
- **非对称**是关键：Q（音/文，"问题"）和 K/V（视频，"证据库"）角色不同，这个**结构化偏置**
  （"用线索去查帧"）比 ① 那种"把所有 token 平等地扔进一个 transformer"**更省数据**。
- 实现：投影到共享维度 → `nn.MultiheadAttention(Q,K,V)` → 残差+LayerNorm+FFN → 池化 → 分类头
  （标准 transformer block，只是 Q 和 K/V 来自不同模态）。

## 3. 白送的可解释性：注意力图

`attn` 权重形状 `(B, S_query, T_frames)`——**每个 query token 在每一帧上的权重**。直接告诉你
**模型判暴力时"看了"哪几帧**。不用额外做 saliency，融合层自带定位式解释，审核场景很有用。

## 4. 6.3 训练：PyTorch Lightning

`LitCrossAttention` 把架构（`cross_attention.py`）和优化解耦：多标签 **BCEWithLogits**（每类
一个独立 sigmoid）、AdamW、逐 epoch 验证 AUC。架构留在一处、优化留在一处，换数据不改模型。

## 5. 实验印证：结构化偏置 vs 数据效率

同为**深度融合**，① early（全对称联合 transformer）和 ⑥ cross-attn（非对称 Q/K/V）走了两条路：

| 数据规模 | ⑥ cross-attn | ① early | 谁赢 |
|---|---|---|---|
| **小（3 模态 774）** | **0.943** | 0.907 | **⑥ 完胜**（结构省数据）|
| **大（2 模态 4502）** | 0.936 | **0.951** | **① 反超**（通用性天花板高）|

- **小数据**：⑥ 的结构化偏置让它 788 就学得很好、夺 §8 三模态表第一；① 还饿着（0.907）。
- **大数据**：喂饱后 ① 更高的天花板赢了；⑥ 稳（std 仅 0.004）但被超。
- **原理**：**cross-attention 用"结构"换"数据效率"**。数据少、或想要"线索定向指帧 + 可解释"时，
  它最划算；数据多到能喂饱全对称的 ①，就该上 ①。**深度融合不是免费的胜利，选哪种看数据量。**

自监督的，以及 Kinetics 监督微调的（为了和 I3D 一样"Kinetics 监督"，公平对打）：

| 视频 K/V | modal 2 | modal 3 |
|---|---|---|
| I3D（任务预提取） | **0.936** | **0.943** |
| VideoMAE-base（自监督直用） | 0.924 | 0.925 |
| VideoMAE-k400（Kinetics 监督微调） | 0.921 | **0.808** |

**两版都打不过 I3D，而且"监督版"更差、还不稳**。一条推翻一条的推理链：

- 第一版自监督 VideoMAE < I3D。**第一反应**：也许因为它没像 I3D 那样监督训练？
- **于是换 Kinetics 监督版——结果更差**（modal 3 崩到 0.808）。**"缺监督"这个解释被推翻。**
  反而印证了另一个已知现象：**在某任务上分类微调过的 backbone 特征会更"专"、迁移性更差**
  （fine-tuned features 迁移常不如预训练 features）；小数据 + 文本 Q 上还overfit不稳。
- **用法也拖后腿**：我们对 VideoMAE patch token 直接 **mean-pool**，很粗，丢判别信息。
- **真正的教训**：**特征"任务对齐"压倒"架构先进/更监督"**。I3D 是为这个暴力基准专门预提取的，
  天生贴合；想真正超过它，多半得**端到端在暴力任务上微调视频编码器**，而不是拿任何现成特征。
  **换更贵/更监督的模型 ≠ 自动更好——特征要对 task。**

## 7. ② vs ⑥：都是 fusion，区别在"对齐的粒度"

一个容易绕晕的概念问题：**② coordinated（CLIP 式）和 ⑥ cross-attention，谁算 fusion、谁算 alignment？**

先把话说清楚：**② 和 ⑥ 都是 fusion 方法**——都在把多模态组合起来做决策。
特别是 **CLIP / coordinated 是经典的 fusion**，具体归类叫 **embedding / model-level fusion
（表示级、中间层融合）**，也正是本项目 ② 的定位。
（容易混淆的点：CLIP 的**训练目标**是对比**对齐**（contrastive alignment），所以在
Baltrušaitis 那套严格分类里它被登记为 "coordinated representation"。但作为**组合多模态做预测的方法**，
它就是 fusion——主流用法如此，本文档口径也如此。**别因为它训练时做对齐，就否认它是 fusion。**）

真正有用的区分是**在什么粒度上建立对应关系**：

| | 怎么组合 | 学不学"子元素对应" | 标签 |
|---|---|---|---|
| ③④⑤ concat / 树 / 平均 | 直接合并 | ❌ 不学 | **纯 fusion** |
| **② coordinated (CLIP)** | 投到共享空间，**整段 embedding** 对类别锚点匹配 | ❌ 不学元素级对应 | **表示级 fusion** |
| **⑥ cross-attention** | Q-K 逐元素算权重 → 加权整合 | ✅ **学"音/文 ↔ 哪几帧"** | **元素级 alignment + fusion** |

- **② 的"对齐"是粗粒度的**：把**整个模态向量**对齐到共享空间/类别锚点，模态之间**从不逐元素相见**。
- **⑥ 的对齐是细粒度的**：注意力权重**就是一次软对齐**，明确回答"这段尖叫对应哪几帧"。

所以：**要说"alignment"，⑥ 的内核（注意力权重）才是元素级对齐；② 是在表示层面做融合。**
两者都是 fusion，只是 ⑥ 多了一层可解释的细粒度对应（也正是它白送注意力图的原因）。

## 一句话总结

Cross-attention = 让"音/文线索"（Q）去 attend 视频的"时序帧"（K/V），把线索和对应时刻**对齐**，
天然解决"切菜 vs 捅人"并白送注意力图。它的**结构化非对称偏置比全对称的 ① 省数据**——小数据
夺魁、大数据被 ① 反超。与 ② 的关系见上一节：**都是 fusion，⑥ 多了元素级对齐。**
