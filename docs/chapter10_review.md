## 1. 评测矩阵设计（10.1）

### 1.1 算法指标：为什么不能只看 F1

审核的代价函数**极度不对称**：漏放一条暴力内容可能导致下架、罚款、舆情；
误杀一条正常内容只是多一次人工复审。所以指标体系必须偏向召回。

| 指标 | 定义 | 在审核场景的地位 |
|---|---|---|
| **Recall** | TP/(TP+FN) | **第一优先**。"宁可误杀不可漏放"= 召回下限约束 |
| Precision | TP/(TP+FP) | 约束项，决定人工复审队列长度（成本），**不是目标** |
| F1 | 调和平均 | **把 P 和 R 等权，与业务代价不符**；只适合对外汇报的单值摘要 |
| **F2** | (1+β²)PR/(β²P+R), β=2 | **召回权重是精确率的 4 倍**，这才是审核口径 |
| ROC-AUC | 排序质量，阈值无关 | **选型看它**：衡量"能不能排对"，与运营阈值解耦 |
| **AP (PR-AUC)** | 正类稀疏时比 ROC 敏感 | 真实流量暴力占比远低于数据集的 37~46%，**生产该看 AP** |
| **Recall@FPR=1%** | 固定误杀预算下的召回 | **最接近业务合同的单一数字** |

### 1.2 工程指标：端到端的正确定义

> **端到端 = 从视频输入到 JSON 吐出**，必须含：视频解码 → 特征提取/抽帧 → 模型前向 → 后处理。

只报"模型前向耗时"是耍流氓——**我们自己在第九章就踩过这个坑**（把 CPU 预处理算进了
GPU 利用率的采样窗口，导致 SM 利用率数字失真）。本章的计时**分段进行**、各自热身、
CPU 段与 GPU 段分开归因。

| 指标 | 口径 |
|---|---|
| Latency **p50/p95/p99** | 审核是异步任务，**队列积压看尾部**，p99 比 p50 重要 |
| QPS | 饱和吞吐。**必须注明 batch 与并发**，否则无意义 |
| GPU Memory | 峰值显存，决定单卡能并存几个模型 |
| **F2 每 GPU-秒** | 把质量和算力放进同一个分母 |

## 3. 结课复盘（10.3）

### 3.1 幻觉的三种形态——实测危害排序与预期不同

| 形态 | 实测 | 判断 |
|---|---|---|
| 类别幻觉（编出白名单外的 category） | **0%** | prompt 里列死枚举就够了，**不是主要威胁** |
| **格式漂移** | 三步标签式 40.0% / 单行压缩式 31.7% / **两种都不匹配 28.3%** | **最高频**，严格解析器失败率 **60%** |
| 判定-解释不一致 | **2.3%**（1/43） | 频率最低但**危害最大** |

**① 格式漂移是约束解码最硬的实证论据。**
我们只给了一种输出格式，模型却在「三步标签式」和「`…。否；none；…` 单行压缩式」之间自由切换，
**越是正常内容越倾向压缩**（没什么可说就简写）。补上第二种格式的解析器只把可解析率从
40% 救到 71.7%，**仍有 28.3% 两种都不匹配**——追正则是永远追不完的军备竞赛。
正解是 **guided decoding 按 JSON Schema 屏蔽非法 token**，从物理上不可能写歪。

**② 最危险的是"自圆其说"型幻觉。** 实测抓到的样本（文艺片 `Before.Sunset.2004`，真实正常，P(yes)=0.03）：

> 画面描述：一个人在车内，似乎在与另一个人交谈或争执。
> **违规判定：是**
> 理由：虽然画面中**没有直接显示暴力行为**，但根据人物的表情和姿态，**可以推测**他们可能在进行
> 激烈的对话或争执，这**可能**涉及到暴力行为。

**模型先承认没有视觉证据，再靠推测得出违规结论**，而 logits 给的是 0.03。
危害在于拦截动作与上报理由**打架**，人工复审看到振振有词的理由容易跟着点"确认违规"。
**系统设计解法：判定只认 logits，解释只作参考，UI 上标注二者不一致。**

### 3.2 RAG：外挂法规知识库

**为什么审核特别需要 RAG**：违规标准**不在模型权重里，而在不断更新的法规与平台细则里**。
改一版法规，模型权重一个字都不会变。**用微调追法规 = 每次改规都要重训**，成本与时效都不可接受。

```
8帧 → VLM 描述画面（模型强项：看懂内容）
         ↓ 描述作为 query
   检索政策库（法规条文/平台细则/判例）  ← 改规只更新这个库，模型不动
         ↓ 命中条文注入 prompt
   VLM 二次判定 → {判定, 条款编号, 理由}
```

**三个收益**：① 时效——改规即时生效；② **可审计**——输出带条款编号（合规刚需）；
③ 抑制幻觉——判定被锚定在检索文本上而非模型先验。

**实测（半失败案例比成功案例更有价值）**：

- **成功**：摩托车行驶片段 → 检索到 P-002 → 判定 none 并**引用条款号**。
- **半失败**：汽车翻滚事故（标签 B6 车祸）——
  - 无 RAG：判定**是** / violence，理由"车辆翻滚严重受损，这属于暴力行为"（按审核口径错了）；
  - 注入 P-004（交通事故属意外事件，不属人为暴力）后：**理由被成功纠正**
    （"属于意外事件，不属于人为暴力"），**但 `违规判定` 字段仍是"是"，类型还漂成了 gore**。

> **结论：RAG grounds the reasoning, not the schema.**
> 检索到的条文改变了模型的论述，却没有传导到结构化字段。
> 生产架构必须是：**检索 → 推理 → 由命中条款机械地推导判定**（条款自带 allow/deny 标记），
> 而不是让模型自由生成 verdict 字段。**RAG 与约束解码是互补而非替代。**

## 4. 本章推翻的两个旧结论（必须记住）

### 4.1 推翻第九章的级联前提

- **第九章说**：小模型 63 µs vs VLM 256 ms，差 ~600×，级联只送 1.8% 流量给 VLM，成本是纯 VLM 的 1.6%。
- **第十章发现**：那个 600× 隐含假设 **"特征是免费的"**。真实线上是新视频，每条都要现抽特征——
  **让 100% 流量过 V1/V2 比全量直接送 V3 还贵 19 倍**（3706 ms vs 188 ms）。
- **修正**：级联第一级必须**只用廉价特征**（砍掉 AST 1041 ms 和 ASR 1822 ms，只留解码 550 + ResNet 42 ≈ 592 ms），
  但**即便如此仍是 V3 饱和批的 3 倍成本**。所以在我们这个规模下，**VLM 全量直跑就是最优解**；
  级联只有在 ①解码可复用/已缓存 ②流量大到 VLM 吞吐成瓶颈 ③第一级用极廉价特征 三者同时成立时才值得。

### 4.2 推翻"纯 VLM 是质量上限"的假设

第九章级联表里"纯 VLM"那行的质量列写的是"（上限参考）"——**那是个没填数的占位**，
因为当时没对全部样本跑 VLM。本章在同切分上实测：**V3 的 F1 0.827 < 小模型 0.935**。
"VLM 是上限"**不成立**。

### 5.1 原来写错的那段

### 5.3 P0-b 帧数扫描：**这是定案证据**

| 帧数 | 视觉 token | ms/clip | AUC | F1@0.5 |
|---:|---:|---:|---:|---:|
| 8 | 512 | 200.3 | 0.9635 | 0.8384 |
| 4 | 256 | **114.1**（−43%）| 0.9526（−0.011）| 0.7979 |
| 2 | 128 | **71.8**（−64%）| 0.9249（−0.039）| 0.7232 |

对三点做线性拟合：

```
latency = 28.7 ms + 0.3349 ms × visual_tokens      R² = 0.99998
→ 8 帧的 200 ms 里，171 ms（86%）花在视觉 token 的 prefill 上
```

**R²=0.99998 的线性关系是计算瓶颈的教科书签名**：延迟与"要算多少 token"严格成正比。
若是 KV 受限，瓶颈会表现为并发排队而非逐 token 的线性成本。
**结论：我们是 prefill 算力受限，KV cache 不是瓶颈。原结论被证伪。**

**连带推翻那条优化建议**：W4A16 量化主要加速 **decode**（访存瓶颈），
对 prefill 这种计算瓶颈**反而可能因反量化开销变慢**。
我们这个"只出 1 个 token"的负载 100% 是 prefill，换 4-bit 大概率不会提速。

**真正该做的优化（实测可行）**：**砍视觉 token**。
**4 帧是甜点位——延迟降 43%，AUC 只掉 0.011。**

**① 重新定阈值是最有效的手段**：V3 的 F2 从 **0.717 → 0.892（+0.175）**；
零样本更夸张，F2 从 **0.215 → 0.772（+0.557）**。最优阈值低到 0.095 / 0.003——
**模型在这个分布上系统性地过度保守**，印证了"校准随分布漂移"。

**② 温度缩放完全无效（F1/F2 一个字没变），这是必然的**：
温度缩放是 `logit/T`，**保号**，所以 `p=0.5`（即 `logit=0`）这个判定边界**在数学上不可能移动**。
它只改变置信度分布的"陡峭程度"，不改变 0.5 阈值下的任何一个判定。
**要改判定必须移阈值，或用非单调/非对称映射（等渗回归）。**

**③ 但校准救不回全部——这里要修正我之前"排序能力在，阈值不在"的说法。**
看最优阈值下的精确率/召回分解（eval 半边）：

| 模型 | P | R |
|---|---:|---:|
| V1 | 0.941 | 0.960 |
| V2 | 0.960 | 0.960 |
| **V3** | **0.696** | 0.960 |

**在同等召回 0.960 下，V3 的精确率只有 0.696，而 V1/V2 有 0.94~0.96。**
也就是说把阈值压低到能抓住暴力时，V3 会**连带误伤大量正常片段**。
AUC 0.951 vs 0.953 看着接近，但 AUC 是全操作点的平均；**在高召回这个真正重要的区间，V3 明显更差**。
所以准确说法是：**差距一大半是校准，但剩下一小半是真实的排序能力差距。**

### 5.6 ⚠️ V2 跨种子方差：第十章"V2 全面最佳"的结论站不住

第十章报 V2 AUC **0.991**，exp10 重跑只有 **0.950**。查了 5 个种子：

| seed | AUC | F1 |
|---:|---:|---:|
| 0 | 0.9771 | 0.9145 |
| 1 | 0.9834 | 0.9533 |
| 2 | 0.9860 | 0.9626 |
| 3 | 0.9917 | 0.9537 |
| 4 | 0.9888 | 0.9677 |
| **均值** | **0.9854 ± 0.0050** | **0.9504 ± 0.0187** |

把 exp10 那次（0.950）算进去，V2 的 AUC 实际在 **0.950–0.992** 之间摆动。
而 **V1 是确定性的逻辑回归，稳定在 0.983**。

> **结论：在这个 295 条单切分上，V1 和 V2 的差距落在噪声里**（V2 0.9854±0.0050 vs V1 0.983）。
> 第十章写的"V2 深度融合全面最佳（AUC 0.991）"**是单次幸运运行的过度解读**。
> 要分开 V1/V2 必须回到 `experiments.md` 的 **4490 条 5 折 CV**——
> 那里 ① early 0.954±0.006 vs ③ concat 0.935 才是有置信区间支撑的真实差距。
> **单切分 295 条的样本量不足以做模型选型。**
